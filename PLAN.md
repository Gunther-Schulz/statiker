# Statiker — the plan (persisted 2026-08-05, pre-compaction)

Working title: **statiker** (naming lineage: bildhauer's sibling —
the Statiker certifies a design will bear load BEFORE construction).
Consumer of this file: the session that writes the skill (the
2026-08-05 beat-the-books session, post-compaction) and the trial
sessions after it. Every subtle decision from the design discussion
is HERE; the conversation is not the carrier.

## Mission and succession

A new, thin, Fable-first design/investigation skill written DIRECT —
no anneal, no spec→render chain, single home. It does not rewrite
clippy; it takes the essence. Succession path (operator decision):
clippy is FROZEN as-is (the in-flight opus-lean acceptance run and
F-2 need it stable; it stays the opus-tier tool). When statiker
works as intended AND opus is validated on it, statiker BECOMES the
new clippy and clippy retires — not the first radical shift as
models improved; clippy was born in Sonnet times.

## The core loop (free, not rigid)

Investigation is made; a design is built; further investigation
either refines it, confirms it, or forces adjustment — repeated
until the design STOPS MOVING and carries sufficient implementation
detail that execution succeeds. No fixed cycle count, no per-cycle
ritual, no ceremony. "Design/investigation cycle" names the motion,
not a schedule.

## The five forcing points (the skill's reason to exist)

Thin means no ceremony. It does NOT mean negotiable evidence,
skippable attack, or design-in-the-implementer's-head. These five
stand guard over the otherwise free loop:

1. **Decision record** — append-only file, decisions WITH bases
   (and the verbatim request + requirements at its head — verify
   reads it, not the conversation). What makes runs gradeable,
   resumable, and delegable ("opus works, fable grades from the
   tracker" is impossible without it).
2. **[READY] = DISPATCHABLE.** The stop rule is a test, not a
   feeling: the design is done when a decision-complete brief could
   be written from it (dispatch skill §1's definition — cite it,
   never restate). Design until you could brief it.
3. **One fresh-context attack on the locked design** by a context
   that did not produce it; iterate ONLY if it bites. (Grounding:
   self-blindness did not improve with tier — same-day evidence of
   Fable duplicating a rule in the commit minting the
   anti-duplication rule; every vet today caught real defects.)
   This is what survives of the whole falsification apparatus.
   (Points 2 and 3 renumbered to the skill's document order,
   0.2.22 — the attack follows the lock.)
4. **Implementation makes no design decisions.** A surprise returns
   to the record (gaps surface, never bridge — dispatch/executor
   skills own the wording).
5. **Verify = executed, isolated, against the recorded
   requirement.** A context that didn't build it runs the real
   checks and pastes their own output.

## THE core mitigation (operator: "YES! that is the core")

The failure clippy was born to prevent is alive in modern form:
**skim-and-build under momentum** — Fable does it too (same-day
observed). The five forcing points ARE the anti-skim mechanism.
Any future thinning that trims them for elegance regresses to the
original disease. Thin in ceremony, never thin in forcing points.

## Lenses: none at birth, fire-born thereafter

No upfront lens list; no lens pass; "lens" is not an artifact class
here. When a real blind spot fires in operation, it is minted as a
**pointed brief clause** — a hunt instruction added where briefs
are composed — carrying its incident as provenance, per the
operator corpus' mint discipline (one grounding observation;
amendment over addition). Evidence for killing the standing pass:
the 2026-08-05 acceptance-run cycles — ad-hoc investigation found
everything; the lens pass echoed bookkeeping.

## Birth-class declaration (what keeps "thin" true over time)

At birth the skill is **enforcement structure + bindings ONLY —
zero capability patches**. Every future addition arrives as a
fire-born patch with provenance + firing log, prunable at
fire-rate reviews. (Thin skills die by accretion; this is the
standing defense.)

## Tier architecture

- **Fable = the judgment desk**: orchestrates, writes briefs,
  forms/records decisions, grades. Its session stays short and
  judgment-dense (spend audit 2026-08-05: 94.2% of fable volume was
  main-session prefix re-billing — the desk must not babysit).
- **Investigation/discovery legs → opus/sonnet subagents** per the
  operator corpus' routing table and the dispatch skill's brief
  discipline. Fable writes pointed briefs to get what a design
  needs — brief-writing IS where lens-judgment lives now.
- **Fresh attack: fable-first** (establishes the CEILING of what
  the best attacker finds), then opus attacks get graded against
  that known ceiling and gaps filled — probe-then-certify, same as
  everything else. Verify tier: per routing/models config.
  CERTIFIED 2026-08-06: probed opus is the attack tier (three-round
  paired comparison, pre-registered criterion met 3-for-3; verdict
  and basis in dev-notes/OBSERVATIONS.md). Fable's attack seat
  closes; its grading/escalation seats stand.

## Record compatibility (measurement is non-negotiable)

The record lives in **`.clippy/runs/`, same decision-line format**
as clippy: `/clippy-stats` reads both, the control-arm comparison
is direct, and a run under either skill is gradeable by the same
machinery. Different skill, shared ledger convention.

## Ecosystem composition (deliberate context-dependence)

Statiker CITES instead of restating: the dispatch skill (briefs,
§1 decision-complete, §2 reports), the executor skill (conduct of
briefed work), the operator corpus (grounding/evidence ethics).
Declared companion dependency on dispatch-guards — the same
companion pattern skill-craft uses for plugin-dev. This is a
recorded DESIGN DECISION overriding skill-craft's
context-independence default: statiker is this operator's tool and
composes with their installed stack; a public extraction would

## Single-home by design — the legitimacy experiment rider

No spec layer. Statiker's operational text is its only home, which
makes it a LIVE experiment for the parked framework-legitimacy
question (anneal-framework BACKLOG): thin single-home vs two-layer
spec→render, graded on real work. Its trial results are named
evidence there.

## Size target

80–150 lines of operational text. If it grows past that, something
is being restated that should be cited, or a patch landed without
provenance.

## Birth process

1. Written in the originating session post-compaction (the
   negotiated design context is the asset).
2. Repo: this one (`~/dev/Gunther-Schulz/statiker`), plugin layout
   per skill-craft canon; released via `/release-plugin` when
   ready; NO GitHub remote until the operator says so.
3. The draft gets **one fresh-context attack** before first use —
   the skill's own discipline applied to its own birth (attack per
   forcing point 3; skill-craft review checklist as the reviewer's
   canon).
4. Then trial on REAL dev work (never synthetic — standing operator
   methodology): natural first vehicles are control-arm arm B
   (which was always secretly "Fable + corpus" — statiker makes
   that arm explicit) and ordinary mid-size tasks.
5. Opus validation on statiker follows the same ladder as
   opus-on-lean (real work, fable grades from the record) → the
   succession decision.
