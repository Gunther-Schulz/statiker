# Scoped codex-only run — numbered proposal to statiker-fd

statiker-c8, 2026-09-13. Phase-1 closed; the readiness set is built and
pushed (0.2.96, pin still at 0.2.92). This is the proposal fd's
sequencing put after the readiness work. Each question carries a
recommendation; none is a menu.

## What the run is for

Probe A saturated and was retired, so the DESK row of the register's
cell table is UNMEASURED for every codex tier — the last unmeasured row
that matters. A live scoped run is what measures it, and it is the one
role a static probe could not reach: the desk's work is the
investigation/design loop and the [READY] judgment, which only exist in
a run.

Phase 1 already answered the operator's pay-or-not question. This run
answers a narrower one: can a codex-only stack hold the DESK seat.

## The registration defect this run must not repeat

Probe A's registration carried a validity gate in the FLOOR direction
(a fail-closed breach fails the arm) and NO symmetric CEILING gate.
Three arms scored 25/25 and the probe certified nothing. Every
criterion below therefore carries its ceiling gate: a pre-registered
statement of what result would mean the arrangement, not the arms,
produced the answer — and at least one Claude arm runs as the ceiling
so saturation is visible rather than inferred.

## Q1 — The object

**Recommendation: a small READY item from `lifecycle`, with its
done-criterion WITHHELD.**

The arrangement: the desk is handed the item's REQUIREMENT only — the
problem statement and its record pointer. The graded done-criterion is
withheld and becomes the pre-registered baseline the desk's own design
is scored against, exactly as probe B scored against a V-line the arms
could not see.

Why this shape: handing a desk a pre-graded READY item short-circuits
forcing points 1 and 2, which ARE most of the desk role. A problem
without its design keeps the loop intact and still gives a ground truth
to grade against.

Why lifecycle: 59 READY items with real graded done-criteria, a live
test suite, and it is neither statiker (a desk running in this repo
breaks the two-session layout the repo's CLAUDE.md settles) nor
beat-the-books (the canonical frame unit stays untouched, per the arc's
own exclusion). dispatch-guards is the fallback at 6 READY items.

OPEN, and fd's call because it is scope: whether a real repo is
acceptable as the object at all given Q5's blast radius, or whether the
run takes a throwaway clone. My recommendation is in Q5.

## Q2 — What "scoped" bounds

**Recommendation: bound the run on four axes, all pre-registered.**

- CYCLES: 3. Past that the run is a trial run, not a scoped probe.
- ATTACK ROUNDS: 1, plus a second only on a bite — the repo's own
  standing floor, not a new rule.
- RECORD SIZE: 60 KB tracker ceiling. The canonical runs reached 287 KB
  and 748 KB; a scoped run that approaches those has stopped being
  scoped, and record volume is one of the two currencies the economics
  lens prices.
- WALL BUDGET: one working session at this desk.

A bound's firing is a DIAGNOSTIC EVENT owing a named cause (CLAUDE.md,
efficiency reviews lead with causes) — not a silent stop.

## Q3 — Tier assignment per leg

**Recommendation: desk = the measured variable, everything else pinned
to its certified tier so the desk is the only thing varying.**

- DESK: terra and astra as two arms. Neither is certified here; that is
  the measurement.
- ATTACK: astra (certified, cross-vendor unique yield).
- IMPLEMENTATION: terra (certified).
- VERIFY: terra (the probe-B assignment reading — 6 of 9 against
  astra's 3, and the tier order INVERTS, so this is not a price pick).

Every uncertified leg now runs as a DECLARED deviation in the tracker
rather than silently, because st-54 landed today (0.2.95). That is what
makes this run readable at all: without it the verify leg would have
selected codex silently for an excluded role.

## Q4 — Pre-registered desk criteria, each with its ceiling gate

**Recommendation: four columns, graded post-run at this desk on a
body-read, with one sonnet arm as the ceiling.**

1. STOP-RULE PLACEMENT — does the desk declare [READY] at a point where
   a decision-complete brief could actually be written? Graded against
   the withheld done-criterion. Ceiling gate: if the sonnet arm and both
   codex arms all land the same call, the item was too easy and the
   column certifies nothing.
2. DESIGN REACH — how much of the withheld done-criterion's substance
   the desk's locked design independently reached. Ceiling gate: as
   above; a criterion every arm reaches whole is a criterion that was
   readable from the requirement.
3. VERDICT-CONTRACT CONDUCT — repairs composed FROM the tools' verdict
   lines rather than improvised around them. This is the measured codex
   weakness (structure-over-contract, replicated twice), so it is the
   column most likely to separate. NO ceiling gate needed in the low
   direction; it carries a FLOOR instead — a desk that improvises past a
   halt verdict fails the arm outright.
4. RECORD DISCIPLINE — append-only held, bases attached, no
   retroactive edits. Floor, not a score.

THE HONESTY FLOOR, as in probe B: a desk that records a verdict no tool
emitted fails outright whatever the columns say. Probe B's discriminator
transfers directly — re-run the tools at this desk over the run's own
record and compare byte-for-byte.

## Q5 — Blast radius, and this is the one I will not decide alone

A codex-only desk must run `--sandbox danger-full-access` — measured,
and now stated as the first fact of the README's codex section. That is
NO sandbox: the model's commands reach the whole filesystem with the
operator's permissions, for the whole run.

**Recommendation: the run takes a THROWAWAY CLONE of the object repo,
on a path holding nothing else, and the real repo is never the working
copy.** The cost is one clone; the alternative is an unsandboxed model
with write reach over the operator's machine for a multi-cycle run. If
fd wants the real repo instead, that is a call I would want stated
explicitly rather than assumed.

Note this is not a permission question for me to route around: the
operator's first-hand run authorization travels operator-side either
way, and it should name which of the two it authorizes.

## Q6 — Does the run dispatch at all, and st-59

st-59 (booked today): forcing points 2, 3 and 4 cite
`dispatch-guards:dispatch` for brief material no codex stack can load —
and nothing checks a brief against an absent form, so the break is
silent at all three.

**Recommendation: the run DOES dispatch, and st-59 is fixed before it
rather than after.** A codex-only run that dispatches nothing measures a
desk that never exercised forcing points 3 and 4 — which is most of what
the desk seat is. And a run that dispatches with the forms absent
measures a desk working without the material the page tells it to use,
which grades the gap rather than the tier.

This is the one item I would put BEFORE the run rather than in the
phase-2 batch. It is small: the fix shape is already settled by
precedent — a sibling of `references/evidence.md`, which is how the page
solved this exact shape for the corpus dependency.
