### A.1 THE PROMPT AS GIVEN — the §9.1 comparand

```text
A command-line tool tracks work items. Each item may carry a "blocked-by" slot naming a decision that must be answered before the item can proceed. A separate ledger file records answered decisions.

Defect: the `close` verb records an ANSWERED decision blocker as "never answered" and writes that inversion into the durable ledger. The `ready` verb resolves the same blocker correctly against the ledger. So two predicates answer one question inside one tool, and the losing one owns the permanent record.

State the acceptance criterion for a correct fix: what exactly must hold, and what would you check to prove the fix is right? Be specific and complete. Answer in under 250 words.
```

### A.2 THE ANSWER AS PRODUCED — the axis-1 evidence body

```text
**Acceptance criterion**

The bug is two predicates answering one question — "is this blocker's decision answered?" — with different (and disagreeing) logic, and the wrong one owns the durable write. A correct fix does not patch `close`'s predicate to also return the right answer; it eliminates the second predicate so `close` and `ready` resolve the blocker through the same code path against the ledger.

Concretely, the fix is correct iff:

1. **Single resolution point.** There is exactly one function that, given a blocker and the ledger, returns answered/unanswered. Both `close` and `ready` call it — grep confirms no second, independent "is answered" check remains in `close`'s code path.
2. **Correctness on the reproducing case.** For an item whose blocking decision is present and answered in the ledger, `close` reports/treats it as answered, and does not write "never answered" (or any inversion) to the ledger.
3. **Ledger integrity going forward.** No code path writes a blocker's answered-state to the ledger without deriving it from the ledger's own existing record — the write is a re-derivation, never a separate judgment.
4. **Agreement, not just one fixed case.** Across the full state space (answered, unanswered, decision missing, malformed entry) `close` and `ready` return identical verdicts for the same ledger — checked by a shared test parametrized over both verbs, not one example.
5. **Red-first proof.** A test reproducing the original scenario (answered blocker, run `close`) fails against the pre-fix code and passes after.
6. **No regression in `ready`**, since it's the correct predicate being reused — its existing tests still pass unchanged.

Pre-existing ledger entries already corrupted by the old `close` are a separate cleanup question, not covered by this criterion.
```
