## 3. Staging

Three laps, each its own release seam with the mandatory
fresh-opus checkpoint review (CLAUDE.md skill-edit review: lap A
exceeds ~50 changed lines AND touches clauses naming record
forms — class 2 read broadly; laps B and C are machine-read
semantics outright). Order is the LEDGER order, and delete runs
first because it shrinks the object every later review must read.

- **Lap A — delete + tighten (page only; tool and tests
  untouched).** Every verdict token stays (parity, §0).
  Incident narrations, superseded hedges, derivations the page
  itself forbids using, restated read-side semantics that survive
  as one principle sentence. Diff-based review; the review brief
  carries the per-clause disposition table (§4) so the reviewer
  attacks "did a deleted clause carry load stated nowhere else"
  — the one question lap A can get wrong.
- **Lap B — precipitate (tool + page + both test files; the
  heavy lap).** Design core: verdict ROUTING moves into the
  tool — each emitted verdict carries a machine-readable
  disposition field (e.g. `route:` naming the seam action from a

  and the contract redesigns to: every emitted verdict carries a
  route from the declared vocabulary; the PAGE names the
  vocabulary and the principles (verdict line booked verbatim;
  unnamed verdict halts; `shas` override), not the per-verdict
  map. `test_contract.py`'s parity pair is REPLACED by the
  route-field parity in the same commit (red-first: the new
  expectations run against the old tool and fail — the

  golden-corpus sweep test (0.2.87 lap, in flight) is an asset
  here: it pins real-corpus behavior across the lap-B tool

## 4. Provenance once text leaves the page

Deleted and precipitated clauses keep their incident provenance
in three already-existing carriers plus one new record this pass
owes per lap:

1. **Existing**: every fire-born clause's mint entry in
   dev-notes/OBSERVATIONS.md (the birth-class discipline made
   them mandatory), and git history over SKILL.md (the trial
   conventions: "history and provenance live in dev-notes and
   git, and rollback is cheap because both record everything").
2. **New, per lap**: the lap's OBSERVATIONS entry carries a
   DISPOSITION TABLE — clause handle (quoted words, enough to
   grep the pre-lap page) → disposition (deleted / tightened-to
   <handle> / precipitated-to <check or route name>) → provenance
   pointer (the mint entry's date / P-id / F-id). This is what
   keeps the fire-rate review able to ask "did a deleted clause's
   class re-fire?" — retirement stays evidence-graded and
   reversible, and the birth-class tenet check at each lap's mint
   records against PLAN's tenet list as usual (all nine, marked).
3. **Re-entry rule**: a class that re-fires after its clause left
   the page re-mints as fire-born with the NEW incident as
   provenance and the disposition-table line as lineage — the
   re-mint is evidence about the pass (a wrong delete), recorded
   as such, not a new orphan clause.

Precipitated semantics additionally keep provenance IN the tool:
the moved check's docstring cites the incident id (the existing
tool convention — e.g. cmd_tripwire cites P19/P18, cmd_verify_gate
cites P30/F124 [measured: statiker_record.py at pin, outline]),
and the battery row that proves it red is the check's living
provenance.

## 8. Economics line (the lens's two currencies)

Cost: 3 releases, 3 opus review rounds (the floor convention —
one honest fresh-context round per shipped change — priced, never
economized), ~2–3 sonnet build lanes per lap, one tool redesign
(lap B). Return: the page drops from 1764 to ~650–750 operational
lines (−57% to −63%) — every future desk session's per-turn
prefix carries that delta for the trial's remaining life; the
routing semantics gain fire-time enforcement (route fields +
battery) in place of read-time prose, which is the medium tenet's
direction of travel; and the fire-rate review gains a per-clause
disposition record it can grade retirements against. What the
pass deliberately does NOT buy: the 80–150 number (§2 — the
honest finding is that the number was a birth-era hypothesis, and
the record already books its re-derivation).
