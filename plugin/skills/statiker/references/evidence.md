# Evidence ethics — the grounding statiker assumes

On a stack without an operator evidence corpus, this file is the
binding source of the ethics the Composition section cites: the
forcing points assume a reader that works this way, and the skill
underperforms without them. Each rule distills an observed failure
class from the source repo ecosystem's operating record — none is
hypothetical. On a stack that carries its own corpus, that corpus
wins and this file stays unloaded.

- **Basis.** A claim or verdict weighs only with its basis — a
  file:line, an executed command's output, a record — or the label
  "unverified". A deferral's basis is the named missing evidence,
  and it must DISCRIMINATE: name the outcome that would flip the
  verdict each way; an awaited measurement consistent with both
  verdicts decides neither.
- **Reach.** A true basis can close a narrower question than the
  one being shut, every sentence staying correct. Before any "not
  possible / not worth it / nothing there": name one design,
  reading, or measurement the basis does NOT rule out — if one
  exists, the question is still open.
- **Refutation.** A load-bearing claim earns one probe designed to
  DISPROVE it before work rests on it. Naming the contrary fact
  and explaining it away is not probing it; confirmation reads do
  not catch what refutation probes catch.
- **Non-events.** An expected nothing — zero findings, zero hits,
  a count that held — is exactly what a dead instrument returns. An
  absence claim stands only once the instrument is shown live on a
  known positive: the same pattern matching a case that IS present,
  or a planted one. A failure to reproduce is not-observed, never
  not-there, until the reported conditions are reproduced.
- **Altitude.** Wrongness lives where the work takes effect — the
  stored data, the running system, the delivered output — and only
  checks at that altitude find it; reviewing what produces the
  effect is not checking the effect. Where the real system can be
  exercised on real inputs, reasoning about it is not a cheaper
  path to the same answer.
- **The check's own output.** A verifier's result is what the check
  itself wrote, never a launcher's, scheduler's, or wrapper's exit
  status — those report that the run happened, not what it found.
- **Definitions.** A wrongness claim — buggy, corrupt,
  misconfigured — asserts deviation from the thing's DEFINITION.
  Exercising the artifact shows what it does, never what it is
  supposed to do; read the definition before the claim ships, or
  label it unverified.
- **Instrument parentage.** Red certifies only the class that
  fired: a defect variant needs its own positive, and instruments
  sharing an author repeat one blind spot across the set. Two
  independently built measurements of one quantity diverging is
  the cheap reach detector; a lone instrument's green is
  indistinguishable from its blind spot.
- **Symptom and cause.** A defect report locates a symptom, not
  the change. Fixes at the symptom site before the root cause is
  articulated spiral; the reported symptom never reliably sets the
  scope.
- **Paraphrase drift.** Labels, status headers, and summaries
  drift from the bodies they stand over; a survey built from
  labels inherits the drift — grade from body-reads. A self-built
  view's own form (which end it took, what order the source was
  in, which namespace an identifier belongs to) is part of any
  claim it carries.
- **Stale premises.** New evidence that kills a premise does not
  revoke what was derived from it: plans built on the old premise
  execute stale unless enumerated and re-derived. The tell is a
  premise and its dependent contradicting inside one output.
- **One variable.** A result equally consistent with the
  hypothesis and with something changed alongside it validates
  neither; a clean re-run exonerates a suspect only for the
  variables the re-run reproduced — enumerate them before booking
  the exoneration.
